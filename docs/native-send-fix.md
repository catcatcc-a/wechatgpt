# 后台发送的电脑本地记录修复

旧的网络 Hook 直接构造发送任务，服务器能收到消息，但电脑微信没有经过创建本地消息和更新会话的流程，因此聊天窗口看不到气泡。

## 修复方式

`native/wechat_send.js` 使用微信自己的文本参数构造函数，通过微信 UI 任务队列进入原生发送协程。微信随后自行创建本地记录、发送消息、更新服务器编号并通知会话。整个过程不激活窗口、不模拟按键、不直接编辑微信数据库。

`scripts/native-send.py` 在每次请求前检查精确微信版本和已加载模块 UUID，限制收件人格式和文本长度，并通过独立 Frida 会话调用原生 helper。回执同时匹配目标会话、原文和微信生成的唯一消息键；只有看到微信生成的本地记录和非零服务器编号才返回成功信号。

MCP 的持久请求账本负责去重。超时、取消、崩溃或结果不明都不会自动换新的请求 ID 重发，也不会回退到旧网络接口或 GUI。

## 本机验收范围

在 Apple Silicon macOS、微信 4.1.11.53 / Build 269109 上：

- 文件传输助手原生后台文本发送取得服务器回执和电脑本地记录编号；
- 电脑微信显示正常的绿色发送气泡；
- 用户确认一条测试消息同时在电脑和手机可见；
- 50 项 Python 测试通过，上游 OneBot Go 测试通过。

2026-10-11 新增微信 **4.1.15.54 / Build 270134** 验收：修正文本类型字段为 `+0xe4` 后，MCP stdio 原生后台发送取得服务器回执和电脑记录；界面看到对应气泡，用户确认手机收到。手机发回的文本通过新版原生批处理观察器及签名回调进入缓存，MCP stdio 可读出。当前共 70 项离线测试通过。

这项验收覆盖文件传输助手文本收发。普通联系人、群聊、媒体消息和其他微信 Build 需要独立适配和验收。

## 版本边界

原生入口的地址、对象布局和模块 UUID 分别记录在两个精确 Build 的 manifest 中。微信升级后必须重新定位和验证；旧版本偏移不能直接复用。历史网络 Hook 发送的消息不会自动补回电脑聊天记录。
