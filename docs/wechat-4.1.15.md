# 微信 4.1.15.54 / Build 270134 适配

当前状态：**文件传输助手双向文本收发已于 2026-10-11 通过本机实测**，manifest 已启用。MCP 后台发送获得服务器回执和本地记录，电脑显示气泡，用户确认手机收到；手机发回的唯一测试文本进入回调缓存，并由 MCP stdio 工具读出。此结论只覆盖 Apple Silicon 上的精确 Build 和上述场景。

## 适配范围

目标为 macOS Apple Silicon，微信显示版本 `4.1.15`、完整版本 `4.1.15.54`、Build `270134`。核心 `wechat.dylib` 的 arm64 Mach-O UUID 为 `8acf7a2f517c32b49dfb47e8849cd444`。

保留原生后台文本发送路径，使微信自行创建电脑聊天记录。接收使用真实手机来信定位到的原生消息批处理入口，生成文本事件并复用 OneBot 签名回调。旧网络响应缓冲区候选在实测中没有触发，已从新版接收路径移除。新版不加载旧的任务替换、媒体上传或下载 Hook；OneBot 的旧 HTTP/WS 发送入口返回拒绝，文本发送统一经过 MCP 原生 helper。

## 定位依据

以下是对本机安装包的静态分析结果，地址属于该精确 UUID，不能泛化到其他 Build。

| 用途 | 4.1.11.53 | 4.1.15.54 | 核对方式 |
| --- | --- | --- | --- |
| 分配 / 释放 | `0x67b35b0` / `0x67b358c` | `0x713c030` / `0x713c00c` | Mach-O 间接符号表中的 `operator new` / sized delete |
| 字符串赋值 | `0x67b2e3c` | `0x713b8e0` | libc++ 导入符号匹配 |
| UI 任务构造 | `0x32718` | `0x31c40` | 指令签名及函数边界 |
| UI 队列提交 | `0x436e480` | `0x4b6e2d8` | 函数体、参数寄存器和调用关系 |
| 文本参数构造 | `0x6bdd8c` | `0x779d74` | RTTI `_878081da` 与 `_cd0907fe`、虚表和构造/析构链 |
| shared ownership 释放 | `0x12aeb4` | `0x127f68` | 原子引用计数、虚析构和弱引用释放 |
| 原生发送提交 | `0x399a8b0` | `0x414c0bc` | RTTI `_a5b4d844`，排除相似重载，核对回调复制结构 |
| 消息记录复制 | `0xd1ee1c` | `0xf5571c` | 完整成员复制布局和回执字段 |
| 回调完成标记虚表 | `0x8fe91c0` | `0x9c04428` | RTTI `_abd300cd` 与析构大小 |
| 接收批处理入口 | 不适用 | `0x32c9774` | 手机真实来信调用栈、`x1` 消息向量及 `0x278` 记录步长 |
| 接收调用点限制 | 不适用 | 返回地址 `0x319aee8` | 仅接受观察到的实时来信路径，排除 UI 历史记录复制 |

文本参数分配大小由 `0x5c8` 变为 `0x610`；参数对象仍位于控制块 `+0x18`，收件人仍在 `+0x90`。文本移到 `+0x5c8`，消息唯一键移到 `+0x580`，文本类型字段经界面真实发送采样确定为 `+0xe4`，子类型为 `+0xe8`；初始候选把类型写到 `+0xe0`，未产生匹配回执，已修正。消息记录中的唯一键从 `+0x250` 移到 `+0x260`。回调结构的 `0x88` 大小和时间字段 `+0x70` 经复制函数核对保持一致。

参数选择由独立 JSON manifest 驱动。安装准备检查磁盘 Mach-O UUID 和指令指纹；运行时再次检查 UUID、入口指令和参数虚表。未知 Build、待验证 profile 和不匹配的指令均在调用前拒绝。

## 维护窗口流程

在完成 `setup.sh`、上游构建及 Frida 17.8.0 下载后，准备已安装的同版本应用副本：

```sh
.venv/bin/python scripts/secure-gadget.py
```

默认仅写入项目的私有 `runtime/security/WeChat.app`，生成独立 Gadget token、注入并重签副本；针对继承父进程沙盒的辅助程序同步重签，独立沙盒扩展保持原样，不操作运行中的微信。重复准备会拒绝覆盖已有副本。

待用户空闲，退出微信，再执行备份和激活：

```sh
.venv/bin/python scripts/backup-wechat.py
.venv/bin/python scripts/secure-gadget.py --activate
```

激活会检查微信已退出、原应用和候选副本与准备记录一致；保留原应用供回退。随后由用户启动微信并登录。先验证无 token / 错 token 拒绝连接，再做无发送的原生参数探测；最后仅向文件传输助手发送带唯一标记的文本，核对电脑气泡、服务器回执及手机接收，并从手机发一条消息验证接收回调。

该 Build 已完成上述验收并启用正式 profile，不需要实验环境变量。未来新 Build 仍须保持 `runtime_verified: false`，仅允许显式指定该 Build 的维护进程试运行；不能通过改版本号或跳过指纹来复用旧适配。

接收仅限实时文本：要求接收状态 `3`、文本类型 `1`、非零服务器编号；按账号、会话和消息编号去重，并限制向量长度和字符串大小。它不导入历史、不下载媒体、不捕获本机发送回执为来信。普通联系人和群聊字段映射具备离线测试，但尚未完成独立真实验收。

旧 4.1.11.53 的两个采样脚本已经限制 Build，避免在新版本运行旧采样偏移。分析产物、微信二进制、截图和测试消息记录留在被忽略的 `artifacts/`，不进入公开仓库。
