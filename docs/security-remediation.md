鉴权防止不知道凭据的连接直接控制 Gadget。管理员和同一 macOS 用户下能读取凭据的进程仍不在该边界内，不能把 token 视为同用户恶意代码的隔离措施。

## 运行状态

已在用户授权的维护窗口中备份原应用、微信容器数据及服务配置，安装同版本 **4.1.15.54 / Build 270134** 的 Gadget 副本并更新后台服务。Gadget、OneBot 和 Webhook 均监听本机回环地址并启用鉴权；GUI 自动发送仍默认关闭。

新版已完成文件传输助手双向文本验收：原生后台发送取得服务器回执及电脑记录，界面已检查，用户确认手机收到；手机来信经过签名回调进入缓存，并由 MCP stdio 工具读取。初始文本类型偏移错误已由真实界面发送样本修正；旧网络接收候选未触发，已替换为严格限制调用点的原生文本批处理观察器。

**普通应用图标启动仍待系统权限验收。** 直接启动主程序可运行；LaunchServices 启动时读取原微信容器返回 `EPERM` 后退出。重签改变应用身份，当前等待用户决定是否在系统设置为微信授予所需的数据访问权限，未擅自开启完全磁盘访问权限。临时启动方式不能作为图标正常启动的证据。嵌套 `WeChatHelper` 的沙盒初始化崩溃已定位到继承配置与重签主程序不一致：安装准备脚本已修复，8 个继承沙盒的辅助应用及相关容器已在独立副本中重签，核心库未变；该副本尚未激活，媒体等辅助功能仍未验收。

重启时还修复了两处启动时序问题：Gadget 先于微信核心库可连接时，脚本可能初始化失败；OneBot 现在必须通过实际 Hook 状态探测才进入服务状态，否则退出供 launchd 稍后重试。更新服务时遇到 launchd 尚未释放旧服务的短暂 EIO，会有限重试。70 项 Python/隔离 JS 测试及完整 Go 测试通过。

应用副本中的 Gadget 配置含私有密钥，不可分享或提交 Git。GitHub 发布仍须用户检查。

后续 [隐私清理与复查](privacy-cleanup.md) 已处理旧 `onebot.log`、截图和原始采样材料。正常使用所需的凭据、缓存和恢复备份保留在私有目录，不进入源码导出。不要分享运行日志或整个 `data/` 目录。
