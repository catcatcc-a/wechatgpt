## Go 告警的解释和处置

本次通过系统已有的本机代理取得 `govulncheck v1.9.0`，查询官方 `vuln.go.dev` 数据库（返回的更新时间为 2026-10-08）。代理只用于审计工具下载和漏洞数据库访问，没有修改项目或服务的网络配置。

| 对象 | Go 版本 | 不同公告总数（含仅版本/包匹配） | 达到符号匹配的公告数 |
| --- | --- | --- | --- |
| 应用补丁后的 OneBot 源码 | 1.26.1 | 41 | 18 |
| 开发目录的 OneBot 二进制 | 1.26.1 | 39 | 24 |
| 实际运行目录的 OneBot 二进制 | 1.26.1 | 39 | 24 |

告警的受影响模块均为 Go 标准库；调用链上的第三方模块只是调用者，不能因此视为这些第三方库自身的漏洞。两个二进制摘要不同，已分别扫描。源码扫描能提供调用链，二进制扫描只证明相应符号存在；两者均不等于实际利用验证。

例如 [GO-2026-6608](https://pkg.go.dev/vuln/GO-2026-6608) 涉及 multipart/MIME 解析内存限制，[GO-2026-6617](https://pkg.go.dev/vuln/GO-2026-6617) 涉及 HTTP/2 服务端崩溃。需要结合具体协议和业务路径判断：本项目默认 JSON 接口不处理 multipart 表单，当前监听使用普通 HTTP，未显式启用 HTTP/2；不能仅凭通用函数匹配就认定这些攻击在当前配置可执行。另有 `GO-2026-4971` 的公告明确只影响 Windows，不能作为本机 macOS 的可利用漏洞。

仍应优先升级工具链并重建，避免继续分发含已知缺陷的标准库。根据[官方发布记录](https://go.dev/doc/devel/release)，同系列 Go 1.26.9 已包含本次扫描所列最新修复；也可评估 Go 1.27.2 或后续受支持的安全版本。仅升级本机 Go 命令不会改变已编译、正在运行的 OneBot；必须重新构建、扫描、测试并部署。此次没有升级工具链、替换二进制或测试漏洞利用。

另对 Webhook 重复 `X-Signature` 和非 ASCII 鉴权头补充了拒绝行为测试，避免解析歧义或字符串比较异常。

## 已核对的保护措施

- 新仓库全部 Git 对象及元数据未检出此前的个人姓名、本机用户路径、真实 OneBot token、私钥或所扫描格式的服务凭据。A-01 所述旧历史已不存在于根仓库。
- 当前 Gadget、OneBot 和 Webhook 仅监听 `127.0.0.1`；未发现这三个服务监听局域网或公网地址。
- 项目和服务运行目录中的数据目录为 `0700`，token 与消息 SQLite 文件为 `0600`；运行根目录为 `0700`，抽查上游日志文件为 `0600`。缓存没有应用层加密。
- Python 配置限制 OneBot/Webhook 使用回环地址；Python OneBot 客户端关闭环境代理和自动重定向。回调先校验原始正文 HMAC，再写入缓存，并限制正文大小。这些限制不能概括为上游所有 Go HTTP 客户端和路由均有限制。
- OneBot 补丁覆盖 HTTP/WS 鉴权，移除测试消息注入入口及 pprof 默认路由；启动时不打印 token。发送结果不明时不会自动重试。
- 运行中的 OneBot `/local_status` 未鉴权请求返回 401，`/debug/pprof/` 返回 404；这些检查未触发 Hook 状态查询或消息发送。
- `.gitignore` 覆盖配置、token、数据库、截图、日志、证据、下载包、备份、微信副本和上游工作副本。整个项目目录仍含这些私有文件，**不可直接压缩整个目录对外分享**。
