# 隐私清理与发布边界

本轮在用户授权下处理本地隐私残留并复查公开内容。检查和清理均在后台进行，没有重启微信、附加新的 Hook、发送消息或创建 GitHub 仓库。

## 已处理的本地材料

- 原地清空运行服务、开发副本、上游日志目录及服务备份中的 8 个 MCP 日志文件，保留正在运行服务持有的文件，不通过重启清理。
- 删除临时截图、GUI/OCR 输出、原始收发样本、联系人测试文件、追踪数据、带本机路径的旧审计输出和旧源码审阅副本。没有把这些材料复制到新备份。
- 将备份、暂存应用和诊断目录的顶层权限收紧为 `0700`，保留的私有清单为 `0600`。
- 保留正常使用所需的 token、MCP 消息缓存、发送去重账本、微信聊天数据、恢复备份和待激活应用的校验清单。它们不属于开源文件；删除整个缓存会影响历史查询和发送去重，因此此次未执行。

文件删除不等于擦除系统快照、系统备份或其他客户端已保存的副本。此次范围是本项目、已部署服务的 MCP 日志及源码发布产物，不承诺对整台电脑作不可恢复的数据销毁。

## 复查方式与结论

- 对全部本地 Git 对象、当前文件名/正文、提交身份、引用、reflog 和仓库配置进行检查；私有值只在内存中比较，报告不输出真实值。
- 比对实际 OneBot/Gadget 凭据、本机用户标识、缓存中提取的会话 ID、联系人信息和较长消息文本。匹配到的通用产品名称位于公开上游链接中，经人工核对属于误报；没有发现真实个人值进入发布内容。
- 提交使用项目中性身份，仓库没有远程。保留上游作者和公开来源属于来源标注，不是本机用户的个人身份。
- 发布检查新增文件名扫描、不可达 Git 对象检查、截图/压缩包等私有文件拦截。命中位置输出为对象 ID 或路径摘要，避免检查日志再次泄露敏感文件名。
- 新增提交/推送钩子和源码导出工具。导出要求受管理文件无未提交修改，先检查全部本地 Git 对象及本机凭据，再从 `HEAD` 导出，并核对归档文件清单和所有者元数据。

验证：81 项离线测试通过，其中新增回归测试覆盖敏感文件名、不可达对象、截图/压缩包拦截、排除未跟踪私有数据、归档所有者元数据及拒绝导出未提交修改。没有为验证读取微信界面或发送消息。

源码归档仅含 Git 受管理的公开源文件，没有 `.git`、本机 UID/用户名、缓存、凭据、截图、日志、恢复备份、微信应用或未跟踪文件。归档包含公开源码自身与提交摘要；Git 提交仍保留正常的版本时间信息。具体最终摘要由导出命令输出。

## 后续操作

本机已启用 `.githooks`。其他维护者克隆后可主动启用；Git 不会自动安装仓库提供的钩子：

```sh
git config --local core.hooksPath .githooks
sh scripts/check-publication.sh
```

钩子不是不可绕过的安全边界，也不能识别所有自然语言隐私。发布前仍检查新增内容；不要使用 `--no-verify` 绕过失败，也不要用 `git add -f` 添加本机资料。CI 同时检查可达历史，但无法读取仅存在于开发电脑上的真实凭据。

完成文档审阅并提交后导出到一个新文件：

```sh
.venv/bin/python scripts/export-public-source.py \
  --output artifacts/open-source-review/wechat-local-mcp-source.tar.gz
```

只分享该源码包或审阅过的 Git 提交，不直接压缩整个项目目录。正常运行会继续产生私有缓存和日志；它们受目录权限和 Git 排除规则保护，不因本次清理成为可公开材料。GitHub 发布仍需项目所有者检查确认。
